# 踩坑记录

开发/使用过程中遇到的问题与解决方案。问题解决后立即记录，避免重复踩坑。

| 日期 | 环境 | 现象 | 原因 | 解法 |
|------|------|------|------|------|
| 2026-09-29 | Windows 10 + Git Bash | 直连 GitHub HTTPS（curl / PowerShell 下载）失败，SSL 错误或超时 | 网络环境无法直连 GitHub HTTPS | 走本地代理：`curl -x http://127.0.0.1:7890`（代理程序开启时可用）；git 的 SSH 方式不受影响 |
| 2026-09-29 | Windows 10 | 系统无 winget，无法 `winget install gh` | Win10 未预装 App Installer | gh 用 Chocolatey 安装（`choco install gh`）；winget 本身从 GitHub release 下载 msixbundle 后 `Add-AppxPackage` 安装 |
| 2026-09-29 | Windows 10 + Git Bash | 新装 gh 后当前/后台 shell 找不到命令；后台任务中导出 PATH 也可能失效 | shell 的 PATH 是启动时快照；后台任务环境更精简 | 用绝对路径调用（`"/c/Program Files/GitHub CLI/gh.exe"`），或新开终端刷新 PATH |
| 2026-09-29 | Windows 10 | 下载 GitHub release 时代理程序未运行（7890 端口不通），curl 走代理失败 | 代理按需开启，不稳定 | npm 类工具优先走已配置的国内镜像（npmmirror 可达）；必须访问 GitHub 时先确认代理已开启（`Test-NetConnection 127.0.0.1 -Port 7890`） |
| 2026-09-29 | Claude 桌面应用 | officecli MCP 注册成功但当前会话看不到工具 | MCP 在会话启动时加载 | 重启会话后生效；在此之前可直接用 officecli CLI（`officecli view/get/query` 等） |
| 2026-09-29 | 银河麒麟 V10 | 新版 PySide6 装不上/启动即报 GLIBC 版本错误 | 麒麟 V10 glibc 为 2.31，而 PySide6 6.10.0 起轮子要求 glibc ≥ 2.34；ARM64 轮子更是要 2.39 | x86_64 上锁 PySide6 **6.9.3**（glibc 2.28）；ARM64 上 Qt 系方案整体不可用。详见 [技术栈选型.md](../技术/技术栈选型.md#关键约束银河麒麟-v10-的-glibc-门槛) |
| 2026-09-29 | 跨平台打包 | 在 Ubuntu 22.04 上打的 Linux 包，拷到麒麟 V10 上跑不起来 | PyInstaller 不打包 glibc，产物继承了构建机的 glibc 版本要求 | Linux 包必须在 glibc ≤ 2.31 的环境构建（Debian 11 / Ubuntu 20.04 容器，或麒麟本机） |
| 2026-09-30 | Windows + Word | officecli 读 `大纲变种.docx` 报"文件正被另一进程使用" | 文档正被 Word 打开着（同目录有 `~$` 锁文件），officecli 以可写方式打开失败 | 先 `cp` 出副本再分析；**正式工具解析大纲时也要注意**：以只读方式读 zip（Python zipfile / fflate 只读不受影响），不要以写模式打开 |
| 2026-09-30 | Vuetify 4.2 / 所有浏览器 | 界面上所有引用 `var(--v-theme-outline)` 的边框、分隔线、底色全部不生效，且**无任何报错**——输入框 focus 才见边框（focus 用的 primary 存在） | Vuetify 4 不再内置 `outline` 主题色 token，`--v-theme-outline` 解析为空，`rgba(var(--v-theme-outline), .9)` 整条声明被浏览器**静默丢弃**；而 `--v-theme-primary` 等已定义 token 的逗号写法正常 | 在 `createVuetify` 主题 colors 里显式补 `outline: '#79747E'`（浅色）/ `'#938F99'`（深色）；排查手法：遍历样式表引用的 `--v-theme-*` 与 `:root` 上实际存在的对比（本会话已做全量校验，missing 为 0） |
| 2026-09-30 | 前端编辑持久化 | 改了切分/转换规则后，用户重新解析仍看到旧规则产出的步骤文本与可疑标记 | 编辑存档按 caseId 恢复时只比对 `version === 1`，而转换语义升级没有递增版本号，旧存档把新结果整体盖掉 | 转换语义（切分写法、静态模板、可疑判定）变化时**必须同步递增** `persistence.ts` 的 `EDIT_STATE_VERSION`；旧版本存档整体作废而不是按字段猜测 |
