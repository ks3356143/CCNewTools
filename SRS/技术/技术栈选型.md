# 技术栈选型

> 状态：**已定案**（2026-09-29）。决策见文末"决策记录"。

**一句话**：Bun 单文件（内嵌 Vue 3 + Vuetify 前端）+ 自研 OOXML 解析 + docxtemplater 渲染，本地浏览器当界面，全离线。

## 选型约束（已知）

- 跨平台是硬性要求（见 [03-非功能需求.md](../需求/03-非功能需求.md)）
- 开发环境为 Windows 10，通过 Git Bash / PowerShell 工作
- 本机访问 GitHub HTTPS 需走本地代理（见 [踩坑记录](../踩坑/踩坑记录.md)），选包管理器/依赖源时注意国内可达性
- **必须能在完全无网络环境下运行**：交付物需自包含，不得依赖 CDN、在线授权、运行时下载
- **目标运行环境包含银河麒麟 V10**（国产化要求），其 glibc 版本与 CPU 架构直接决定 GUI 库能否使用

## 关键约束：银河麒麟 V10 的 glibc 门槛

麒麟 V10 的 glibc 为 **2.31**（国产平台如 3A5000/申威为 2.28），内核 4.19/5.4/5.10，自带 Python 3.8.10、Qt5。

各 GUI 绑定在 **Linux 轮子**上的实际可用性（2026-09 核实，来源为阿里云/清华 PyPI 镜像的轮子文件名）：

| 绑定 | x86_64 最低 glibc | Linux ARM64 | 许可证 |
|------|------------------|-------------|--------|
| PySide6 6.11.2 | 2.34 ❌ | 2.39 ❌ | LGPL |
| PySide6 6.9.3 | **2.28 ✅** | 2.39 ❌ | LGPL |
| PyQt5 5.15.11 | 2.17 ✅ | **无 Linux ARM 轮子** ❌ | GPL/商业 |

结论：

- **x86_64 麒麟 V10 可用**，但 PySide6 必须锁 **6.9.3**（6.10.0 起 glibc 要求跳到 2.34）
- **ARM64（飞腾/鲲鹏）不可用**：PySide6 6.9.2 起 ARM 轮子一律要求 glibc 2.39；PyQt5 无 Linux ARM 轮子。只剩自行编译 Qt 一条路，工程量极大
- **龙芯 / 申威**：无官方轮子
- `PySide6-Fluent-Widgets` 为纯 Python 包，无 glibc 约束
- PyPI 上 PySide6 仅保留近期版本（当前最低 6.9.2），旧版本已下架，选型时不能假设"降级到老版本"总能兜底

**打包约束**：PyInstaller 不打包 glibc。若在 Ubuntu 22.04（glibc 2.35）上打包，产物在麒麟 V10 上会报 `GLIBC_2.34 not found`。Linux 包必须在 glibc ≤ 2.31 的环境构建（Debian 11 / Ubuntu 20.04 容器，或麒麟本机）。

**上线前必须核实**（在目标麒麟机器上执行）：

```bash
ldd --version && uname -m
```

若 `uname -m` 输出 `aarch64`，则 Qt 系桌面方案整体不可行，需转向编译型语言的单文件方案（见下方候选方案）。

## 候选方案（初步罗列，未评估）

| 方案 | 优势 | 劣势 | 适用形态 |
|------|------|------|----------|
| Python | 数据处理生态强、上手快 | 打包分发较麻烦 | CLI / 脚本 |
| Node.js | 生态丰富、跨平台好 | 数据处理需额外库 | CLI / Web |
| Go | 单文件跨平台编译、分发极简 | GUI 生态弱 | CLI / 后台 |
| Rust | 性能好、单文件分发 | 开发成本较高 | CLI / 后台 |
| Tauri / Electron | 桌面 GUI 跨平台 | 体积/复杂度增加 | 桌面 GUI |

## 决策记录

| 日期 | 决策 | 理由 | 参与 |
|------|------|------|------|
| 2026-09-29 | **运行时：Bun** | 可 `bun build --compile` 出单文件；**可从 Windows 交叉编译出 Linux x64 和 Linux ARM64**，一条命令解决信创多架构分发。实测 Windows 上编译三平台产物全部成功 | 用户拍板 |
| 2026-09-29 | **界面：Vue 3 + Vuetify + 本地浏览器** | 浏览器人人都有，**不需要 WebView2**（内网机器最容易卡这里）；界面美观程度上限最高；用户点名要 Vuetify | 用户拍板 |
| 2026-09-29 | **文档渲染：docxtemplater** | MIT 许可、唯一依赖；**支持表格行循环**（项目技术含量最高的一块），实测免费核心功能可用 | 用户拍板 |
| 2026-09-29 | **文档解析：自研（直接读 OOXML）** | 与渲染层同技术路线，不引入第二套 Word 引擎；单文件真正自包含（省掉 33MB 的 OfficeCLI 二进制）；毫秒级 vs officecli 导出 HTML 的 3.2 秒 | 用户拍板 |
| 2026-09-29 | **不使用 OfficeCLI 作为运行时依赖** | 它不支持行循环，且会给单文件分发增加负担。OfficeCLI 仍是我（Claude）开发时查看 Word 的工具 | 用户拍板 |
| 2026-10-08 | **大文档处理：分块解析 + 分批渲染合并 + 落盘交付**（[10-大文档处理](../设计/10-大文档处理.md)） | 42MB 正文实测全链路爆内存 24GB+；分块解析保业务规则零迁移（xmldom 仅在顶层元素粒度使用），渲染按测试项分批即用即弃，产物落盘免浏览器大内存传输 | 用户立项（"尽量少占用内存，折中方案直接生成 docx 告知目录"） |

### 被否决的方案（保留理由，避免重复讨论）

| 方案 | 否决原因 |
|------|---------|
| PySide6 + PySide6-Fluent-Widgets | **麒麟 V10 跑不了**：系统 glibc 2.31，PySide6 6.10+ 要 2.34；ARM64 轮子更是要 2.39，麒麟 ARM 版完全不可用 |
| Flet | `flet-desktop` 只有 14KB 空壳，**首次运行要联网从 GitHub 下载 Flutter 客户端**——无网环境直接失败。正是用户之前在 NiceGUI 上踩过的同类坑 |
| NiceGUI / pywebview 原生窗口 | 需要 WebView2 运行时，内网机器常缺失 |
| Go + 自研模板引擎 | 分发最好，但文档模板引擎要自己写（行循环、跨 run、合并单元格），风险最高 |
| 纯 OfficeCLI 管线 | `merge` 不支持行循环 |
| 大文档 SAX 流式解析全替换（saxes 等） | 解析规则（标题栈/表格判别/编号还原）全部迁移重写、新增依赖，回归风险大；与"顶层元素分块 + 逐块 DOM 化"内存收益等价（分块见 10 号设计 4.2）。留作分块方案不够时的后备 |
| 大文档只提高上限不动架构 | 42MB 正文实测两个 bun 进程合计 24GB+（本机内存占满），直接放开上限只会让内网机器崩溃 |
| 前端强制"每批 ≤150 用例"分批交互（数据结构改成"卷"） | 解析侧分块后全量领域对象 ~200-300MB 放得下，无需改数据结构；交互层数千用例性能留观察项，卡了再上分页载入（批大小即 150） |
