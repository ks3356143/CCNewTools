# 08 打包与交付

> 状态：**已定稿**（2026-09-30，与第 6 节测试策略同日过定）

## 一、构建流程

```
bun install
   ↓
vite build            前端产物（Vue3 + Vuetify + 图标字体，全部本地化）
   ↓
bun build --compile   三平台交叉编译（均在 Windows 开发机完成，已实测可行）
   ↓
产物：测试文档生成工具_v<版本>_<平台>.<ext>
```

| 平台 | 产物 |
|------|------|
| Windows x64 | `测试文档生成工具_v1.0.0_win-x64.exe` |
| Linux x64 | `测试文档生成工具_v1.0.0_linux-x64` |
| Linux ARM64 | `测试文档生成工具_v1.0.0_linux-arm64` |

一条命令 `bun run build` 出全部产物。交叉编译目标名以 Bun 实际版本语法为准（实现时核实）。

**内嵌资源**（全部打进二进制，不外置）：前端产物、`测试说明模板.docx`、`测试记录模板.docx`、Material Design Icons 字体、版本信息。模板要改就得重新打包——这是单文件形态的已知取舍，换取拷贝即用。

## 二、版本号

语义化 `v主.次.修订`：

- **主**：输出文档格式/业务规则不兼容的变更
- **次**：解析规则、功能新增
- **修订**：缺陷修复、界面微调

版本号三处可见：启动控制台横幅、界面"关于"、编辑记录 JSON（便于排查历史数据是哪版产生的）。

## 三、运行时行为

1. 双击 → 起本地 HTTP 服务，**只监听 127.0.0.1**
2. 端口默认固定，被占则自动顺延并提示实际地址
3. 自动打开系统默认浏览器；未自动打开时控制台显示 `http://127.0.0.1:<端口>` 供手动访问
4. 关闭 = 关闭控制台窗口（服务随之结束；编辑已持久化，不丢数据）

数据目录（与 [05-界面设计](05-界面设计.md) 持久化方案一致）：

```
<exe目录>/
├── 测试文档生成工具.exe
└── 数据/
    ├── 编辑记录/   每份大纲一个 JSON（自动保存）
    └── 日志/       滚动保留最近 5 个
```

`数据/` 不可写时整体回退到 `%USERPROFILE%/CCNewTools/` 并提示一次。

## 四、交付物

1. 三个平台的可执行文件
2. **一页《使用说明》**（放 exe 旁，也内置在界面"关于"里）：
   - 双击启动、浏览器访问方式
   - 编辑记录存在哪里、换电脑怎么迁（整个 exe + `数据/` 文件夹一起拷）
   - 常见问题：文件被 Word 占用、杀软误报、浏览器未自动打开

## 五、升级与回滚

- **升级 = 覆盖 exe**，`数据/` 目录不动；编辑记录 JSON 带版本号，新版本读到旧格式做兼容迁移，迁移失败则忽略该记录并提示（不炸主流程）
- **回滚 = 换回旧 exe**；保留上一版 exe 于 `数据/旧版本/` 下由用户自行决定是否留存
- 模板变更随版本走，旧版生成的文档不受影响

## 六、已知风险与对策

| 风险 | 对策 |
|------|------|
| **Bun 产物在麒麟 V10 实机不兼容**（此前仅有编译成功证据） | [07-测试策略](07-测试策略.md) 的实机验收为最后一道关；若失败，回退方案是 Debian 11 容器内低 glibc 环境构建（参考踩坑记录 PyInstaller 条目）或改用 Node 单文件方案 |
| 杀毒软件误报单文件 exe | 交付说明写明处理方式（加入白名单）；先在内网一台机器试用确认 |
| 麒麟自带浏览器内核过老渲染异常 | 验收清单观察项；必要时为前端降级 CSS 特性（实现期控制） |

## 七、发版检查单

1. [07-测试策略](07-测试策略.md) 的发版验收清单全部通过
2. 三平台产物在对应平台可启动（Windows 本机 + 麒麟实机 + ARM 实机或标注未验证）
3. 产物文件名与版本号一致，"关于"页版本正确
4. 断网环境从拷贝到生成文档全流程走通
