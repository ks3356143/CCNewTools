# 03 转换层

> 状态：**已与用户确认**（2026-09-29）

## 职责

把解析层的领域模型翻译成渲染层要的模板数据。**所有业务规则集中在这一层**，解析层和渲染层都不含业务规则。

## 一、核心概念对应关系

以 `A星指令参数管理` 为例：

| 概念 | 实例 | 来源 |
|------|------|------|
| **测试项** | `A星指令参数管理` | heading 6 的标题 |
| 测试项标识 | `XQ_SU_ZLPA` | 表格第 1 行第 4 格 |
| **测试子项 / 用例** | `参数查询正常功能`、`参数新增正常功能`…… 共 5 个 | "测试方法"格里 `n.名称（标识）` 编号条目 |
| 用例名称 | `参数查询正常功能` | 同上，括号前的部分 |
| 测试需求标识 | `XQ_SU_ZLPA_SU01` | 同上，括号里的标识 |
| **用例标识** | `YL_SU_ZLPA_001`、`YL_SU_ZLPA_002`…… | **工具生成**，规则见下 |

**一个测试子项 = 一个测试用例**（用户明确确认）。

## 二、用例标识生成规则

```
用例标识 = 测试项标识去掉 "XQ" 换成 "YL"  +  "_" + 3 位序号
```

| 测试项标识 | 生成的用例标识 |
|-----------|---------------|
| `XQ_SU_ZLPA` | `YL_SU_ZLPA_001` … `YL_SU_ZLPA_005` |
| `XQ_SU_ZLMB` | `YL_SU_ZLMB_001` … `YL_SU_ZLMB_016` |
| `XQ_DC` | `YL_DC_001` |
| `XQ_AC_SCZQ` | `YL_AC_SCZQ_001` |

**要点**：

- 序号**在每个测试项内从 001 重新开始**
- **从测试项标识推导，不是从用例级标识推导**。文档审查的用例标识是 `YL_DC_001`（源自 `XQ_DC`），**不是** `YL_DC_DC001`（源自 `XQ_DC_DC001`）——用户明确强调过
- 静态类型（文档审查 / 静态分析 / 代码审查）的用例标识规则**与普通类型相同**，都是 `YL_<测试项标识后缀>_001`

### 两个编号体系并存（不要混淆）

同一行里会出现两个序号对不上的标识，这是**预期行为**：

| 字段 | 值 | 含义 |
|------|-----|------|
| `caseId`（标识） | `YL_SU_ZLPA_001` | 用例侧编号，工具按顺序生成 |
| `itemId`（测试需求标识） | `XQ_SU_ZLPA_SU01` | 需求侧编号，大纲里已写好，照抄 |

## 四、排序规则

`cases` 数组按大纲中的出现顺序排列（测试类型 → 测试项 → 用例），保证输出文档的章节顺序与大纲一致。

## 五、步骤拆分（输入及操作 / 期望结果与评估标准）

**2026-09-30 用户确认的新写法**（旧版"动作截断在关键词前"的写法已废弃）：

- **动作 = 完整步骤文本**（去结尾标点——用户要求步骤文本不以标点结尾）；
- **期望 = 最后一个预期关键词之后的内容**（删除"是否"字样——含紧跟关键词的前缀与句中，如"查询结果是否正确显示"→"查询结果正确显示"；去结尾标点）；
- 期望允许与动作部分重复（"输入及操作文字多一点，期望重复点"）；
- **纯操作步合并**：没有预期关键词的步骤（如"点击新增按钮，输入信息。"）文本并入下一个带验证步骤的动作开头——参数新增 4 步变 3 步；末尾仍未并入的纯操作步保持原样，记"期望结果为空"可疑。

**静态三类型（文档审查/静态分析/代码审查）完全按老项目写法**（用户确认）：这三个类型的步骤是固定模板化内容（静态分析 2 步、代码审查 1 步、文档审查 2 步，文本见 `rows.ts` 的 STATIC_TEMPLATES），不产生可疑标记，用户无需审核；且这三类无中间层、测试项与测试类型同名，转换时 `showItem` 置空，避免"2.1 文档审查"标题下再出现重复的"2.1.1.1 文档审查"测试项标题（2026-09-30 用户实测反馈）。

**期望结果的两种来源**（见 [02-解析层 9.5](02-解析层.md)）：

- 大纲"通过准则"格按用例分桶且条目与（合并后的）步骤一一对应 → 直接用作期望结果与评估标准；
- 否则按上述关键词切分，从方法文本中切出。

转换层按解析层标记的来源模式处理，不重复判断。悬空小标题行（如"查询标识："）在解析层已被丢弃，不会进入步骤列表。

可疑判定启发式（供界面使用）：

- 期望结果为空（纯操作尾步）——**当前唯一实现**；用户在界面补写期望后自动解除，也可点"确认无误"保留
- ~~期望以固定动词开头~~（**2026-09-30 废弃**：新切分语义下期望为断言式文本如"显示新增的参数信息"，不再以动词开头，旧检查会误标几乎全部步骤）
- 步骤文本中间出现未拆分的编号痕迹（如「，2）」「；3）」）与用例段落数 ≥ 切出步骤数 × 2——设计保留项，尚未实现

完整的三级问题分类与各阶段错误清单见 [06-错误处理](06-错误处理.md)。
