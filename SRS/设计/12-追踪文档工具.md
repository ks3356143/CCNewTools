# 12 追踪文档工具（工具二）

> 状态：**已确认**（2026-10-10，用户拍板三项决议：追踪表独立成档 / 两步轻流程 / 共用项目库）
> 来源：用户需求——"用户输入大纲、自动生成大纲和说明的追踪文档，然后用户复制里面表格贴入自己表格"

## 定位

从测试大纲生成**"大纲 ↔ 需求规格说明"追踪关系文档**（.docx）。现测试说明里「需求的可追踪性」章的追踪表独立成档，用户打开后把表格复制贴入自己的文档模板。

与工具一共享：解析层（[02-解析层](02-解析层.md) 全部规则）、转换层追踪表数据、项目库（[09-本地数据管理](09-本地数据管理.md)）、异常文件拦截（[06-错误处理](06-错误处理.md)）。

## 流程（两步）

```
第 1 步：选择大纲                第 2 步：生成与获取
┌──────────────────────┐      ┌──────────────────────────────┐
│ 拖入/点击上传 .docx    │      │ ✔ 解析成功：N 项 / M 用例      │
│ （含解析概要+问题清单） │  →   │ ┌──────────────────────────┐ │
│                      │      │ │ 追踪表预览（浏览器内渲染）  │ │
│ 最近项目（共用项目库）  │      │ │ [ 复制表格 ] ← HTML 直贴 Word│ │
│ 打开即免上传直接生成    │      │ └──────────────────────────┘ │
└──────────────────────┘      │ [ 下载追踪文档 .docx ]        │
                              └──────────────────────────────┘
```

- **无核对屏**：追踪表是机械映射，没有"切分可疑"需要人工确认
- 解析概要与问题清单（错误/告警/提示）照常展示，但**不拦截生成**（与工具一"带告警照常生成"口径一致）
- 最近项目点击 → 免上传重解析 → 直接进第 2 步

## 输出物定义

**追踪文档 = 标题（需求的可追踪性）+ 追踪表**，列与数据复用现转换层 `traceRows`（[03-转换层](03-转换层.md)/[04-渲染层与模板](04-渲染层与模板.md)）：

| 列 | 字段 | 来源 |
|----|------|------|
| 序号 | `no` | 生成时重编号 |
| 需求规格说明章节 | `srsChapter` | 大纲"追踪关系"行 |
| 需求规格说明描述 | `srsDesc` | 同上 |
| 大纲章节号 | `outlineChapter` | 解析层（Word 自动编号还原） |
| 测试项 | `itemName` | 测试项表格首格 |
| 测试项标识 | `itemItemId` | 测试项表格标识格 |
| 用例名称 | `caseName` | 用例标题 |
| 用例标识 | `caseId` | 转换层生成 |

- **排除口径与工具一一致**：编辑存档里标记"排除"的用例不进追踪表（共用项目库时同一份大纲在工具一排除过，两工具产出保持一致）
- **全局参数不参与**：追踪表不含 configName 等参数，无参数卡

## 表格复制（剪贴板主通道）

用户工作流的核心动作是"复制表格贴入自己文档"，除下载 docx 外提供**「复制表格」按钮**：

- 复制 `text/html` 剪贴板（带边框表格），粘贴到 Word 直接成为真表格（格式保留）
- 同时携带 `text/plain` TSV 兜底（老 Excel/纯文本场景）
- 剪贴板 API 需安全上下文（localhost/127.0.0.1 天然满足，与现有服务一致）

## 模板策略

- 新增 `模板/追踪文档模板.docx`：**从测试说明模板 XML 手术抽取**——保留「需求的可追踪性」标题段 + 追踪表（含题注）整段，剥掉其余章节
- 用户手改的追踪表样式（外框加粗 sz12、表头加粗、五号字、题注五号居中）**原样保留**——与工具一同一张表，一份样式两处受益
- docxtemplater 循环标签 `{#traceRows}…{/traceRows}` 随抽取段自然继承
- 打包脚本模板清单随新模板自动覆盖（实现时验证嵌入完整性）

## API 设计

```
POST /api/trace/generate
  body: { outline: {name, hash}, cases: CaseRow[] }
  ← { ok, doc: { name, sizeKB, base64?, path? } }
```

- 数据推导与 `/api/generate` 同源（送来的用例数据推导 traceRows，保持与核对结果一致）
- **落盘交付沿用 [10-大文档处理](10-大文档处理.md) 规则**：写 `数据/生成/<项目id12>/`，≤10MB 附 base64 下载、>10MB 只给路径；追踪文档每例远小于记录行，常见规模都在 base64 档
- 响应只出一份文档；大文档水位保护（RSS 水位线）随共用渲染函数天然继承

## 前端两屏实现

| 屏 | 复用 | 新增 |
|----|------|------|
| 第 1 步 | Screen1 的拖拽上传区、解析概要、问题清单、最近项目列表（抽公共组件或轻量复制，实现时按影响面定） | 屏文案按工具二语境微调（"生成追踪文档"按钮） |
| 第 2 步 | 落盘交付/下载双轨交互（Screen3 模式） | 追踪表预览（HTML 表格，大数据量时分段渲染防卡）+ 复制按钮 |

- 预览表格行数 = 用例数（大文档 29686 例时 3 万行 DOM 不可行）→ **预览最多渲染前 200 行 + "共 N 行，完整内容见下载文档"提示**；复制按钮不受限（数据驱动，不依赖 DOM）
- 顶栏 stepper 两步：「选大纲 → 生成文档」

## 错误处理

- 异常文件六类拦截（[06](06-错误处理.md) 导入阶段）原样生效
- 解析零用例（大纲无测试项）→ 生成按钮禁用 + 提示"未识别到测试项"
- 生成失败 → toast + 服务日志（现有错误链路）
