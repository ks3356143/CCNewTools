# 02 解析层

> 状态：**已与用户确认**（2026-09-29），规则已在真实大纲上**全量验证通过**

## 职责

读入测试大纲 `.docx`，输出领域模型。不含任何业务规则。

## 一、范围界定

**只处理"测试项及方法"这一节**（当前大纲里是 6.2）。

定位方式：找标题文本匹配 `测试项及方法` 的 heading，从它开始，到下一个 level ≤ 2 的标题为止。

范围外的内容（测试依据、测试环境、测试组织、附录的检查单与对照表等）全部跳过。

## 二、标题与章节号

### 章节号是 Word 自动编号，不是正文文字

大纲里的 `6.2.1.4.1.1` 这类编号**不存在于段落文本中**，是 Word 按 `numbering.xml` 自动生成的。

还原方式：

1. 解析 `numbering.xml`，建立 `numId → abstractNumId → 各级 numFmt / start` 映射
2. 遍历段落，读其 `w:pPr/w:numPr`（`w:numId`、`w:ilvl`）
3. 按 `ilvl` 维护计数器：遇到某级标题则本级 +1，其下所有级别清零

本大纲全部标题共用 `numId=1`、`numFmt=decimal`、各级 `start=1`，计数器法已验证与文档目录一致。

### 标题嵌套不固定（**关键**）

实测 37 张测试项表格所挂标题的层级：

| 挂载层级 | 数量 | 例子 |
|---------|------|------|
| level 4 | 3 | `6.2.1.1 文档审查`、`6.2.1.2 静态分析`、`6.2.1.3 代码审查` |
| level 5 | 17 | `6.2.1.5.1 A星有效载荷控制指令生成准确率测试` |
| level 6 | 17 | `6.2.1.4.1.1 A星指令参数管理` |

三种嵌套形态同时存在：

```
6.2.1.1 文档审查                     ← level 4，表格直接挂这
6.2.1.4 功能测试                     ← level 4（测试类型）
  6.2.1.4.1 A星模板功能测试           ← level 5（中间层，没有表格）
    6.2.1.4.1.1 A星指令参数管理       ← level 6，表格挂这
6.2.1.5 性能测试                     ← level 4（测试类型）
  6.2.1.5.1 A星有效载荷控制指令生成准确率测试   ← level 5，表格挂这
```

**因此每个测试项要记录一条完整的"标题路径"**（从测试类型到测试项的所有祖先标题），而不是只记一个标题。

- 测试类型 = 最近的 level-4 标题
- 测试项 = 表格前面最近的那个标题（4/5/6 级都可能）
- 路径示例：
  - 文档审查 → `[{lvl:4, num:"6.2.1.1", text:"文档审查"}]`
  - A星指令参数管理 → `[{lvl:4, "6.2.1.4", "功能测试"}, {lvl:5, "6.2.1.4.1", "A星模板功能测试"}, {lvl:6, "6.2.1.4.1.1", "A星指令参数管理"}]`

本大纲里该特征唯一（37 张表全部符合，无其他表误命中）。

## 四、提取字段

按**行标签**取值而不是按行号，格式微调（多行少行）不会崩：

| 行标签 | 取值 |
|--------|------|
| 测试项名称 | 第 2 格 → 测试项名称；第 4 格 → 测试项标识 |

（表格固定 7 行：测试项名称 / 追踪关系 / 需求描述 / 测试项描述 / 测试方法 / 充分性要求 / 通过准则）

## 五、段落提取（**容易踩的坑**）

同一张表格里，"测试方法"单元格的段落有两种渲染形态：

| 测试项 | 单元格结构 |
|--------|-----------|
| 文档审查 | 7 个普通段落（步骤编号 `1）2）` 是**字面文本**） |
| 静态分析 | 2 个普通段落 + **自动编号列表** |
| 代码审查 | 2 个普通段落 + **自动编号列表**（4 项） |
| 普通类型（功能测试等） | 全是普通段落（编号是字面文本） |

也就是说**静态类型的步骤在 Word 里是自动编号列表**，正文里根本没有 `1）` 这两个字——用正则 `^\d+）` 切分会直接漏掉整段。

解析时必须：

1. **同时处理普通段落和列表项**，并保持文档顺序
2. **剔除自动编号的渲染标记**（否则文本会被污染成 `46）编程准则检查：…`）

> 实测代码审查的列表自动编号显示为 `46）47）48）49）`——大纲自身的编号定义有问题，不影响我们（说明文档的序号由模板重新编）。

## 六、切分用例与步骤（**核心规则**）

### 用例切分

"测试方法"单元格里，匹配下面规则的段落 = **用例标题行**，开启一个新用例：

```
^\d{1,3}\s*(.+?)\s*[（(]\s*([A-Za-z]{2}_[A-Za-z0-9_]+)\s*[)）]\s*$
```

- 第 1 个捕获组 = 用例名称（剥离前导的「.」「、」分隔符）
- 第 2 个捕获组 = 测试需求标识（如 `XQ_SU_ZLPA_SU01`）

**容错**（实测 A星 V1.10）：编号后的「.」「、」分隔符允许省略，如
`8宏动作与模板映射修改异常功能（XQ_SU_HHZM_SU08）`。编号后紧跟「）」的是普通
步骤（`m）` 开头），名称为空的也不是标题。

### 综述来源

"测试项描述"单元格里：

- 若同样有 `n.名称（标识）` 标题行 → 标题行**后面紧邻的段落**是该用例的综述
- 若整个单元格只有一段、没有标题行 → 这段是**该测试项下所有用例共用的综述**（18 个测试项属于这种）

### 步骤切分

标题行之后的段落按下列规则切成步骤：

```
1. 匹配 n.名称（标识）的段落        → 开启一个新用例
2. 标题行后第一段若以「：」结尾       → 引导句
3. 自动编号列表项                   → 新步骤；
     若该列表项以「：」结尾           → 其后的列表项并入同一步骤
     （实测依据：静态分析格"统计软件质量度量信息，包含：" + 四项度量条件 = 1 步）
4. 以 m） 开头的段落                → 新步骤（剥离 m） 前缀，序号列独立）
5. 以「：」结尾的段落（非首段）      → 新步骤，其后的非编号段落并入
     （无内容并入的悬空小标题按 9.1 丢弃）
6. 其余段落：
     上一段以「；」结尾  → 并入上一步骤
     上一段以「。」结尾  → 新步骤
     否则                → 并入上一步骤
```

**引导句处理**：仅 2 个用例有（文档审查、代码审查），计划**并入第 1 步的开头**，避免信息丢失。（待用户最终确认）

## 八、兜底与告警

- 用例标识与测试项标识不一致（原文有 `XQ_SU_ZLQQ` 配 `XQ_SU_ZLQX_SU01` 的笔误）→ 不报错，以用例标题里的标识为准，**收集成告警在界面上提示**
- "测试方法"里一个用例标题都没有 → 整个单元格当一个用例，所有段落当步骤
- **标题悬空（2026-10-01 用户要求显式告警）**：「测试项及方法」节内的标题若既没挂测试项表格、也没有更深层子标题 → 告警 `HEADING_NO_TABLE`（"标题「6.2.2.4.1 ×××」下没有测试项表格（可能写漏），该标题无测试项产出"）。容器标题（配置项测试、功能测试等有子标题的）不告警；检查点在标题被顶掉时（含节末终结与文档在节内直接结束的兜底）。层级号不受影响——章节号始终按 Word 自动编号的真实层级累计，容器只是路径节点不参与结构判断（2026-10-01 用户定稿："无所谓什么配置项、什么分系统，只关心测试项，标题章节号的层级和大纲一致"）
- **标题下有表但不是测试项表格（2026-10-01 对抗审查）**：表格首格不是「测试项名称」→ 该表跳过，其标题若因此无产出 → 告警 `TABLE_NOT_ITEM`（"下的表格不是测试项表格，已忽略"），与写漏的 `HEADING_NO_TABLE` 区分
- **手打编号回退（2026-10-01 对抗审查）**：标题无自动编号（numPr 缺失）而正文自带「6.2.1.4.1 名称」式编号 → 编号还原为章节号、文字剥掉编号前缀，记一条 `MANUAL_CHAPTER_NUM` 提示；有自动编号的正常大纲不受影响（实测零回归）
- **空标题跳过**：只挂编号没写文字的标题不进栈（进栈会以空名参与类型/组判定）

## 九、大纲变种实测与补充规则（2026-09-30，BCD星大纲）

拿到另一颗星的完整大纲（`文档S/大纲变种.docx`，同为 37 张测试项表）做了全量普查，暴露出以下与 A星大纲不同的形态。**以下规则均已按实测结果定稿**。

### 9.1 悬空小标题行（**必须丢弃**）

"测试方法"格里会出现以"："结尾的**独立小标题行**，后面紧跟编号步骤，本身不带任何内容。实测 A星大纲**没有**这种行；BCD 变种的 参数管理 表里有 3 处：

```
2）在参数列表下方的查询输入框中输入参数标识，……；
查询标识：                ← 悬空小标题行（无作用）
3）在查询输入框中输入参数名称，……；
```

甚至有 `XXXX：`（同事忘了删的占位符）。现行"以「：」结尾的段落 → 新步骤"规则会把它误切成一个**空步骤**。

**判定**：以"："结尾、非用例标题行、**其后直到下一个步骤/标题之间没有可并入的正文**（即按现行规则切出来的步骤内容为空）。

**处理**：不生成步骤，整行丢弃，收集一条**信息级提示**（"已忽略小标题行：查询标识："），界面上可在解析概要里看到，不算告警不算错误。

> 这样判定比"短于 N 个字"更稳：只丢弃真正切不出内容的行，正文里以"："结尾的真步骤不受影响。

### 9.2 测试项描述没有子项 → 所有用例共用综述（已实测确认）

BCD 变种 37 张表里有 11 张（人机交互界面、安全性、余量、强度、恢复性、安装性、兼容性等）"测试项描述"格**只有一段、无子项标题行**，而"测试方法"里有 1~5 个用例 → 这段描述就是该测试项**所有用例共用的综述**。与第六节规则一致，已被实测确认。

### 9.3 测试项描述与测试方法的子项数量可能不一致（**以测试方法为准**）

实测 BCD 变种"宏动作与指令模板映射管理"：描述格 8 个子项，方法格只有 7 个（"修改异常功能"在方法里没写）。

**处理**：用例一律以"测试方法"里的标题行为准；描述格的子项综述按**需求标识**匹配到用例，描述里多出来的子项**忽略并记一条告警**；方法里有用例但描述里找不到对应综述的，回退用共用综述（若存在），都没有则综述留空并记告警。

### 9.4 标识不一致的形态扩展

第八节的兜底（用例标识 vs 测试项标识不一致）之外，实测发现**描述格与方法格之间**也会有笔误：BCD 变种 准确率测试 的描述格写 `XQ_AC_SCZQ_AC01`、方法格写 `XQ_AC_SCZQL_AC01`（多个 L）。规则不变并扩展：**一切以"测试方法"里的用例标题标识为准**，描述格标识只用于综述匹配，匹配不上就按 9.3 处理。

### 9.5 通过准则格的对应形态（**2026-09-30 用户提供样例定稿**）

实测的两份大纲里，"通过准则"格**全部为空**（"充分性要求"格是两句固定模板话，无需解析）。用户随后提供了第三种形态的样例（截图确认），规则如下：

**该形态的通过准则格有自己的用例结构**：

```
1、检索武器资源信息人机界面元素测试（XQ_SU_JSWQ_SU01）
1）软件展示当前页面所在页面层级信息……；
2）软件检索结果统计栏展示统计检索结果数量；
2、正常检索武器资源信息功能（XQ_SU_JSWQ_SU02）
不同检索类型（武器类型、目标、行业分类、标签、关键词）：
1）软件检索结果统计栏展示统计检索结果数量，数量与武器库该类型数量一致；……
```

**处理规则**：

1. **按用例标题分桶**：准则格内的 `n、名称（标识）` 行与测试方法的用例标题同规则识别（顿号分隔、缺分隔符均容错），每个用例一个准则桶；
2. **小标题行自动丢弃**：用例标题下以"："结尾的行（如"不同检索类型（……）："）无实际内容，丢弃并记提示——与 9.1 同性质；
3. **逐条配对**：准则条目 `n）` 剥离编号后，按序号与测试方法的步骤一一配对——**测试方法 = 用例输入（动作），通过准则 = 预期（期望）**，期望结果不再做关键词切分；
4. **配不上的回退**：方法用例在准则格无对应桶 → 关键词切分；~~条目数与步骤数不一致 → 回退关键词切分并记告警~~（**2026-10-01 修订**：只要配到准则就一律不切分，条数不等按 9.9 规则三处理——按序配对 + 留空待补 / 并入末步，并记告警）；
5. 续行（上一条未以。；结尾的无编号段）并入上一条；无法归属的孤立段落记提示。

每用例记录"期望结果来源：通过准则 / 方法切分"，界面上展示。

### 9.6 标题层级跳级（规则已覆盖，实测确认）

BCD 变种里性能测试、接口测试、边界测试、安全性测试等是 level-4 标题**直接跳到 level-6** 的测试项（中间没有 level-5），说明"记录完整标题路径"的规则是对的，按现有方式处理即可。

**表格直接挂 level-5（2026-10-01 用户实测补全）**：真实大纲还存在「level-5 标题下直接挂表格」的形态（如 6.2.1.5.1 BCD星指令生成准确率测试，全大纲 17 处）。此时该 level-5 标题是**测试项本身**而非中间层，解析必须置 `groupName = null`（判定：level-5 是栈顶、即表格的直接标题），否则组名与项名相同，生成文档（h3+h4 重名）和树里会多出一层重复标题。

### 9.7 样式级标题编号（**2026-09-30 用户实测发现**）

真实大纲的标题编号不在段落直接格式里，而是**挂在标题样式上**（styles.xml 的 heading 1~9 各带 `numId=1, ilvl=0~8`）。只读段落 `numPr` 会导致所有章节号为空（追踪表"大纲章节号"列、记录"测试需求分析"行全空，且合成测试数据手工填了章节号掩盖了此 bug）。规则：**有效 numPr = 段落直接格式 优先，否则回退 pStyle 对应样式的 numPr**（`styles.ts` 的 `styleNumPr`）。

### 9.8 描述格手打编号残痕清理（2026-09-30 用户样例）

共用综述的多段直接拼接会出现"…V1.012）软件用户手册…"错乱——Word 自动编号不在正文，但作者手打的"2）"残留。规则：描述格段落进入综述前剥掉段首 `数字+）/）、` 编号残痕，多段按 `\n` 拼接（模板渲染为软换行）。

### 9.9 准则一问一答式变种 + 方法格综述（**2026-10-01 用户样例"1.test测试大纲"定稿**）

用户构造的变种测试项（6.2.1.4.2 变种写法测试项）暴露了三种此前未覆盖的写法：

**规则一：是否切分先判准则**。转换前先看本用例是否在通过准则格配到条目——**配到了就不做关键词切分**（步骤是纯输入，"查看"等词保留在动作里），期望逐条取准则；没配到才走关键词切分（旧行为）。

**规则二：步骤清单按写法选**。配到准则后：

- 步骤**含**预期关键词 = 拆分式写法（A星 9.5 形态）→ 纯操作步并入验证步后与准则配对（合并后等数）；
- 步骤**不含**关键词 = 纯输入写法（新变种）→ **原样一一对应**（合并会破坏 1:1，此前"两个子项各并成一步"的错误根因）。

**规则三：条数不等的兜底**（全部不回退切分）：

| 形态 | 处理 | 级别 |
|------|------|------|
| 准则条数 = 步骤数 | 逐条配对（主路径） | — |
| 一句话准则（1 条） | 全部步骤共用该句 | 提示 |
| 准则少于步骤 | 按序配对，多出的步骤期望留空待补（可疑，补写后自动解除） | 告警 |
| 准则多于步骤 | 按序配对，多余条目并入最后一步 | 告警 |

**规则四：方法格综述**。用例综述可能写在**方法格子项标题下**（有人写、有人忘写）。标题后、首个步骤前的普通段落暂存为 `methodSummary`，归宿由准则裁决：**配到准则 → 转正为用例综述**（优先于描述格的共用综述，描述格只补缺，不覆盖）；**没配到 → 退回为第 1 步**（与旧解析一致——真实大纲"静态分析"等项的标题后普通段是动作句而非综述，此退回保证黄金基线 37/110/528 逐字节不变）。

**规则五：重名标识轮转**。两个子项故意同标识（样例中两个用例与准则格两个桶均为 XQ_SU_BZXF_SU01）→ 按出现顺序轮转配对（第 1 个用例配第 1 个桶），绝不都配第一个。准则格标题下的**普通段落**（一句话准则）记为一条准则项，不再当孤儿丢弃；无桶可配的条目记提示忽略。

**规则六：无标题的编号条目（2026-10-01 对抗审查）**。准则格写了 `1）2）…` 逐条预期却**没写用例标题**：单用例的表格按唯一用例整体配对（告警 `CRITERIA_NOTITLED` 留痕）；多用例无法归属 → 告警 `CRITERIA_ORPHAN_ITEMS` 不静默。散文段落（真实大纲准则格的普通句子）不参与此逻辑，维持静默。

> 实测验证：真实大纲（37/110/528）与 1.test 文档其余 19 个用例的新旧解析**逐字节一致**，仅两个变种用例按新规则变化（各 3 步、期望取准则、综述归位、零可疑）；编辑存档版本闸 2→3（准则式大纲的步骤文本变化，旧存档作废——当前无受影响存档）。

### 9.10 标题层级镜像（**2026-10-01 用户样例"2大纲变种-XXX分系统"定稿**）

用户在 2大纲变种 中插入了「XXX分系统」中间层（容器），暴露出层级判断写死的问题。定稿规则：

**规则一：解析层记录完整路径**。每个测试项的 `path` = 标题栈全链（从「测试项及方法」节下第一级到挂载标题，容器/分系统只是路径节点）。层级判断**不再依赖固定的 level-4/level-5**——"测试类型 = 最近的 level-4"旧规则废弃（分系统层插入后容器占 L4、类型降到 L5，全部错位）。

**规则二：生成文档按路径序号逐级出标题**（转换层，见 [04-渲染层](04-渲染层与模板.md)）：path[0]→h2 … path[4]→h6，编号自动续成大纲层级（2.1 / 2.1.1 / 2.1.2.4.1 逐段对应 6.2 下层级）；跳级自动压缩、相邻同名层去重（静态类型不重复出标题）、path 超五层丢最浅容器层并告警 `PATH_TOO_DEEP`。

**规则三：typeName/groupName 降级为兼容字段**（树导航、静态识别、生成日志沿用）：typeName = 路径最深层往上第一个命中 `KNOWN_TYPE_NAMES` 清单的层（静态三类型 + 功能/性能/接口/边界/人机交互界面/安全性/余量/强度/恢复性/安装性/兼容性测试；容器名"BCD星…配置项测试"以"测试"结尾但不在清单，不会误当类型）；清单未覆盖的新类型回退"测试/审查/分析结尾的最深层"。groupName = 类型层与项标题之间的中间层（多层拼接，相邻为 null）。

**规则四：层级镜像后老文档的变化**（用户原则："无所谓什么结构，章节号层级和大纲一致"）：真实大纲/大纲变种的 BCD 容器层（6.2.1）此前被静默丢弃（类型直接挂 h2），现在镜像为 h2——项编号从 2.4.1.1 变为 **2.1.4.1.1，逐段对应大纲 6.2.1.4.1.1**，比旧版更贴合大纲层级；1.test 无容器层，输出结构不变。

> 实测验证（2026-10-01）：四文档统计零变化（37/110/528、37/110/528、15/21/114、32/46/240）、零错误；2大纲变种层级树与用户期望逐行一致（XXX分系统 h2 → 容器 h3 → 类型 h4 → 项 h5）；"删除分系统层"变体（子树整体提升一级）同样通过；编辑存档无需升版本（步骤文本与 caseId 未变，树/面包屑按 typeName/groupName 兼容字段展示不受影响）。
