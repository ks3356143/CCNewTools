# 04 渲染层与模板

> 状态：模板改造**已完成并验证**；渲染层实现未开始

## 一、技术选型

**docxtemplater 3.71.0**（MIT，唯一依赖 `@xmldom/xmldom`）

选它的原因：

- **支持表格行循环**——这是整个项目技术含量最高的一块（步骤行数动态），已实测验证是**免费核心功能**
- 支持段落级条件，用来控制标题只输出一次
- 与解析层同为"直接读 OOXML"的技术路线，不引入第二套 Word 引擎

**注意**：`officecli merge` 只支持 `{{key}}` 简单替换，**不支持行循环**，所以渲染不能走 OfficeCLI。

## 二、模板改造（已完成）

两个模板原本是 **docxtpl（Python + Jinja2）** 语法，已改成 **docxtemplater** 语法。

### 语法对照

| 原语法（docxtpl） | 新语法（docxtemplater） |
|---|---|
| `{{item.mingcheng}}` | `{mingcheng}` |
| `{%p for item in tables%}` … `{%p endfor %}` | `{#cases}` … `{/cases}` |
| `{%p if item.is_begin == '1' %}` … `{%p endif %}` | `{#showType}` … `{/showType}` |
| `{%tr for i in item.zuhe%}` / `{%tr endfor%}`（各占一整行） | **删掉这两行**，改成 `{#steps}` 放步骤行首格、`{/}` 放末格 |
| `{{shijian}}` | `{testTime}`（顺手统一命名） |

### 关键点

- **只改文字，不动样式和结构**——所以 Word 的自动编号（`1 测试用例` / `1.1 xxx` / `1.1.1 xxx`）照常工作，编号由 Word 生成
- 模板里的标题段落**只有占位符文本**，编号不在正文里（与大纲同理）
- 占位符在 Word 里**会被拆成多个 run**（`{{item.csxbs}}` 实际是 `{{item` + `.csxbs` + `}}`），docxtemplater 能处理

### 改造方式

用 **OfficeCLI batch** 批量改的（说明模板 21 项、记录模板 24 项，全部成功），只改文本不碰样式。

## 三、模板变量清单

### 测试说明模板

```
1 测试用例                    (heading 1，自动编号)
{#cases}
  {#showType}
    1.1 {typeName}            (heading 2)
  {/showType}
  {#showGroup}
    1.1.1 {groupName}         (heading 3)   ← 中间层，待加
  {/showGroup}
  {#showItem}
    1.1.1.1 {itemName}        (heading 4)   ← 待加
  {/showItem}
  [表格]
{/cases}
```

表格（每用例一张）：

| 行 | 内容 |
|----|------|
| 1 | `用例` |
| 2 | 测试用例名称 `{mingcheng}` / 标 识 `{caseId}` |
| 3 | 追踪关系：`软件测试依据：软件测评大纲` + `测试需求分析：{chapter} {itemName}` + `测试需求标识：{itemId}` |
| 4 | 测试用例综述 `{summary}` |
| 5 | 用例初始化 `{init}` |
| 6 | 前提和约束 `{constraint}` |
| 7 | 测试步骤 |
| 8 | 序号 / 输入及操作 / 期望结果与评估标准 |
| 9 | `{#steps}{no}` / `{action}` / `{expect}{/}` |
| 10 | 终止条件（固定文本） |
| 11 | 通过准则（固定文本） |
| 12 | 设计人员 `{designer}` |

### 测试记录模板

结构同上，差异：

- 表头是 `1.1 {typeName}` / `1.1.1 {itemName}`（用 `csx_type` / `csx_name` 的语义）
- 步骤行多两列：`{actual}`（实测结果，默认空）、`{result}`（通过与否，默认"通过"）
- 多出：执行状态 `已执行` / 测试时间 `{testTime}` / 测试人员 `{tester}` / 监测人员 `{monitor}` / 问题单标识（空）/ 备注 `/`
- 追踪关系是**单个占位符 `{trace}`**（说明模板是内联三段式）
- 模板后部还有附录（文档审查单、代码审查单、静态分析结果记录、未覆盖情况），**是静态内容，原样保留**

## 四、已验证的渲染效果

用真实大纲数据渲染，结果正确：

```
1 测试用例
  1.1 文档审查              ← 测试类型，只出现一次
    1.1.1 文档审查          ← 测试项
      [表：2 步]
  1.2 功能测试
    1.2.1 A星指令参数管理
      [表：5 步]
      [表：2 步]            ← 同一测试项的第二个用例，不重复标题
    1.2.2 A星指令生成
      [表：1 步]
```

- 标题自动编号正确（`1.1` → `1.2` → `1.2.1` → `1.2.2`）
- 步骤行数正确展开
- 表格边框、列宽、字体全部保留
- 记录的附录表格原样保留
