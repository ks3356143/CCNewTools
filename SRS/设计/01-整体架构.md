# 01 整体架构

> 状态：**已与用户确认**（2026-09-29）

## 交付物形态

**一个单文件可执行程序**（Windows / Linux x64 / Linux ARM64 各一个），双击即用，零安装、零联网。

```
┌──────────────────────────────────────────────┐
│  单个可执行文件（Bun 编译产物）                │
│                                               │
│   ┌─────────────┐        ┌────────────────┐  │
│   │ 本地 HTTP   │◄──────►│  解析 / 转换    │  │
│   │ 服务        │        │  / 渲染         │  │
│   └──────┬──────┘        └────────────────┘  │
│          │                                    │
│   ┌──────▼───────────────────────────────┐   │
│   │ 内嵌前端资源：Vue3 + Vuetify + 图标字体 │   │
│   │ （全部打进二进制，无任何外链）          │   │
│   └──────────────────────────────────────┘   │
└───────────────┬──────────────────────────────┘
                │ 只监听 127.0.0.1
                ▼
         用户浏览器（系统自带）
```

**启动流程**：双击 → 本地起服务 → 自动打开浏览器 → 选大纲 → 解析 → 核对编辑 → 生成并下载。

**为什么是浏览器界面**：浏览器人人都有，**不需要 WebView2**（老工具/同类方案在信创内网机器上最容易卡在这里），且界面好看程度上限最高。

## 内部三层

每层输入输出都是纯数据，可独立测试、独立替换：

| 层 | 职责 | 输入 → 输出 | 文档 |
|----|------|-------------|------|
| **解析层** | 读大纲，抽取标题层级、章节号、测试项表格 | `大纲.docx` → 领域模型 | [02-解析层](02-解析层.md) |
| **转换层** | 业务规则：用例标识生成、步骤切分、默认值 | 领域模型 → 模板数据 | [03-转换层](03-转换层.md) |
| **渲染层** | 套模板出文档 | 模板数据 + 模板.docx → 输出.docx | [04-渲染层与模板](04-渲染层与模板.md) |

**为什么单独分出转换层**：这一层最容易变（用例标识规则、默认值、追踪关系格式都属业务约定），隔离开来以后改动不用碰解析和渲染。

## 数据流

```
大纲.docx
   │  ① 解析层
   ▼
领域模型（测试类型 → 测试项 → 用例 → 步骤，含标题路径与章节号）
   │  ② 转换层
   ▼
模板数据（cases[] 扁平数组，含 showType / showItem 标志位）
   │  ③ 渲染层
   ▼
测试说明.docx + 测试记录.docx
```

## 明确不做的事

- **不调用 OfficeCLI**。工具自身用 JS 直接解析 OOXML，与渲染层（docxtemplater 也是直接读 OOXML）技术栈一致，单文件真正自包含。
  （OfficeCLI 是我（Claude）在开发过程中查看 Word 用的工具，不是运行时依赖。）
- **不依赖任何在线资源**。无 CDN、无在线授权、无运行时下载。
- **不读大纲的 6.2 节以外的内容**。测试依据、环境、附录检查单等一律跳过。
