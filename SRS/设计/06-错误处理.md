# 06 错误处理

> 状态：**已定稿**（2026-09-30，用户委托制定："错误处理你来定"）
> 配套：解析兜底规则见 [02-解析层](02-解析层.md)，界面呈现见 [05-界面设计](05-界面设计.md)

## 一、设计原则

1. **局部问题不炸全局**。解析"能收多少收多少"：某张表、某个用例有问题，只影响它自己（留空 + 记录问题），绝不因局部格式不对放弃整份文档。
2. **一切自动决策留痕**。工具自己做的每个假设（以方法格标识为准、丢弃小标题行、回退共用综述……）都必须在界面上可见、可追溯。
3. **问题三级分类**：

| 级别 | 含义 | 生成文档时 |
|------|------|-----------|
| **错误** | 该表/用例无法正常产出（缺标识、零步骤……） | 未修复也未排除时**拦截生成** |
| **告警** | 已按假设处理出了结果，但建议人工核对 | 不拦截 |
| **提示** | 纯告知，数据无影响（丢弃小标题行等） | 不拦截 |

4. **失败不丢工作**。任何一步失败，用户已做的编辑不丢（持久化方案见 [05](05-界面设计.md)）。
5. **静默清单**。以下是"正常写法差异"，不算问题、不产生任何提示：空段落、全角/半角括号与标点差异、步骤编号跳号（输出文档序号由模板重编）、自动编号列表的编号剔除、描述与方法的用例顺序差异。

## 二、问题清单（按阶段）

### 1. 文件导入（第 1 屏）

全部为**终止性错误**：不进入解析，显示原因，回到选择文件。

| 场景 | 检测方式 | 提示文案 |
|------|---------|---------|
| 不是 .docx | 扩展名 + zip 魔数（PK） | 请选择 .docx 格式的大纲文件 |
| 旧版 .doc | OLE2 魔数（D0 CF 11 E0） | 这是旧版 .doc 格式，请用 Word 另存为 .docx 后再导入 |
| 文件损坏 | zip 打不开 / document.xml 缺失或 XML 非法 | 文件损坏或不是有效的 Word 文档 |
| 文档加密 | zip 内含 EncryptionInfo / EncryptedPackage | 文档已加密，请解密后重新另存为 .docx |
| 文件被占用 | 读取报 Permission denied | 文件被其他程序占用（可能正被 Word 打开），关闭后重试 |
| 空文件 / 超大 | 0 字节 / zip > 100MB 或 document.xml > 20MB | 文件为空 / 文件 xx.xMB 超过 100MB 上限，请确认是大纲原文 / 文档正文 xx.xMB 超过 20MB 上限，大纲规模异常庞大，请拆分后分批导入 |
| 找不到"测试项及方法"章节 | 标题文本匹配失败 | 未找到『测试项及方法』章节，请确认导入的是测试大纲 |
| 章节内无测试项表格 | 无首格为"测试项名称"的表格 | 本章内没有测试项表格 |

### 2. 解析阶段（**非终止**：照常进入核对屏，问题进三级清单）

| 场景 | 级别 | 处理 |
|------|------|------|
| 表格缺行（按行标签找不到，如缺"测试项描述"行） | 告警 | 缺失字段留空，界面可补 |
| 测试项标识缺失（第 1 行第 4 格为空） | **错误** | 用例标识生成规则无从执行，标识留空，界面可补 |
| "测试方法"整格无用例标题行 | 提示 | 整格当一个用例（[02 第八节](02-解析层.md) 兜底） |
| 用例零步骤 | **错误** | 界面标红；可手工补步骤或排除该用例 |
| 用例标识与测试项标识 / 描述格标识不一致 | 告警 | 一律以"测试方法"用例标题为准（[02 第八节、9.4](02-解析层.md)） |
| 描述格与方法格子项数不一致 | 告警 | 以方法为准，综述按标识匹配（[02 9.3](02-解析层.md)） |
| 综述匹配不到、也没有共用综述 | 告警 | 综述留空，界面可补 |
| 悬空小标题行（"查询标识："类） | 提示 | 丢弃（[02 9.1](02-解析层.md)） |
| 期望结果为空（切分可疑） | 告警 | 界面琥珀色高亮，人工修或"确认无误"（[03 第五节](03-转换层.md)）；旧"未以固定动词开头"检查已废弃（2026-09-30，新切分语义下期望不再以动词开头） |
| 通过准则条数少于/多于步骤数 | 告警 | 不回退切分：按序配对，多出步骤期望留空待补（可疑）/多余条目并入末步（[02 9.9](02-解析层.md)） |
| 标题悬空（节内标题无表也无子标题） | 告警 | 告警 `HEADING_NO_TABLE`（可能写漏测试项表），界面问题清单与第二屏"告警"胶囊均可见（[02 第八节](02-解析层.md)） |
| 标题下有表但非测试项表格（首格≠「测试项名称」） | 告警 | `TABLE_NOT_ITEM`，该表跳过（[02 第八节](02-解析层.md)） |
| 测试项标题层级超过 5 层 | 告警 | `PATH_TOO_DEEP`：最浅的容器层不在生成文档中体现（h2~h6 只有五槽，项标题必须落 h6 内；[02 9.10](02-解析层.md)） |
| 用例标识撞号（多测试项同 itemId，复制粘贴未改 XQ） | 告警 | `CASE_ID_DUP`：用例清单/追踪表无法区分、编辑存档按 caseId 键控会互相串扰，请改标识（[03](03-转换层.md)） |
| 准则格无标题的编号条目 | 告警 | 单用例按唯一用例配对（`CRITERIA_NOTITLED`）；多用例无法归属忽略（`CRITERIA_ORPHAN_ITEMS`）（[02 9.9](02-解析层.md)） |
| 标题无自动编号、正文手打编号 | 提示 | `MANUAL_CHAPTER_NUM`：按正文编号还原章节号（[02 第八节](02-解析层.md)） |
| 一句话准则全步骤共用 | 提示 | 准则仅 1 条时应用到全部步骤（[02 9.9](02-解析层.md)） |
| 通过准则格子项无用例对应 | 提示 | 忽略（标识笔误等；准则按标识配对，重名标识按出现顺序轮转） |
| 步骤文本中疑似含未拆分编号（出现"，2）""；3）"类痕迹） | 告警 | 界面高亮，人工拆分 |
| 剔除自动编号后正文为空的段落 | 提示 | 跳过 |

### 3. 转换阶段

| 场景 | 级别 | 处理 |
|------|------|------|
| 全局参数缺测试人员 / 监测人员 | 拦截 | 生成按钮提示，不进入生成（原型已实现） |
| 单测试项用例数超 999 | 提示 | 序号扩为 4 位（实际几乎不可能） |
| 用例标识撞号（多个测试项用相同 itemId，复制粘贴未改 XQ） | — | **照原样生成、不告警（2026-10-01 用户拍板）**：转换什么就生成什么，用户看生成文档自行修改；转换层告警已并入 /api/parse 响应（此前被丢弃、界面不可见，2026-10-01 修复） |

### 4. 渲染生成阶段（第 3 屏）

| 场景 | 级别 | 处理 |
|------|------|------|
| docxtemplater 渲染抛错 | 错误 | 捕获并定位到用例，**不产出半成品文件**；数据已在第 2 屏核对过，此处出错概率极低 |
| 磁盘 / 临时目录写入失败 | 错误 | 提示磁盘问题，编辑不丢，可重试 |
| 生成中途程序退出 | — | 临时文件下次覆盖，无副作用 |

### 5. 运行环境

| 场景 | 处理 |
|------|------|
| 前端与服务层断连（本地服务停止） | 前端提示"本地服务已停止，请重启程序"；编辑已持久化，重启自动恢复 |
| 默认端口被占 | 启动时自动换端口 |
| 编辑记录 JSON 损坏 | 忽略该记录、按无记录处理并提示，绝不影响解析主流程 |

## 三、"测试方法格式有误"专项（高发点）

格式有误无法穷举，策略 = **确定性规则 + 启发式检查 + 人工兜底**：

1. **确定性规则**：用例标题正则、步骤切分、悬空小标题、编号列表处理——全部见 [02-解析层](02-解析层.md)，已用两份真实大纲验证。
2. **启发式告警**（宁可多报，由人裁决）：
   - 用例零步骤；
   - 步骤文本中间出现未拆分的编号痕迹（如"，2）""；3）"——多半是同事用了不认识的编号写法，整段被并进步骤）；
   - 一个用例的段落数 ≥ 切出步骤数 × 2 → 提示"可能有编号格式不统一的段落被并入步骤"。
3. **人工兜底**（第 2 屏配套能力，正式版实现、原型未含）：
   - 步骤行支持**新增 / 删除 / 上移 / 下移**——零步骤可补、拆不开可拆（新增一行再把文本挪过去）；
   - 出错用例可标记**"不生成此用例"**，生成时跳过并在概要中说明数量。

## 四、界面呈现

- **第 1 屏解析概要**：统计徽标 `✔ 37 项 / 112 用例 · 2 错误 · 5 告警 · 3 提示`，红/琥珀/灰蓝三色 alert 分组列出，**每条可点击**，跳到第 2 屏对应用例。
- **第 2 屏**：有错误的用例在树上标红点；用例面板顶部列出该用例自己的问题条。
- **生成拦截**：存在未处理错误（未修复也未排除）时点"生成文档"，弹窗列出清单，可一键跳转。
- **第 3 屏生成日志**：提示级信息（丢弃了哪些小标题行等）也打进日志留档。

## 五、错误文案规范

- 说清**发生了什么 + 该怎么办**，不道歉、不含糊："这是旧版 .doc 格式，请用 Word 另存为 .docx 后再导入"。
- 意外错误统一模板：`处理时出现意外错误：<摘要>。你的编辑已保存，可重试；若反复出现请反馈。`技术详情折叠可展开（便于排查），默认收起。
