# 09 本地数据管理（项目制）

> 状态：**已与用户确认**（2026-10-01，用户选定"存源文件副本"方案）

## 职责

以"**项目**"方式管理本地数据：一份大纲 = 一个项目。用户在界面上能查看、打开、删除历史项目，`数据/` 目录不再只进不出。

## 核心模型

- **项目 ID = 大纲内容 SHA1 前 12 位**（内容寻址）。同一文件重复上传自动归并为同一项目，不会存两份
- 大纲升版（V1.10 → V1.11，哈希变化）→ 新项目；旧项目保留，由用户决定删除
- 项目目录 = 元信息 + 编辑记录（复用 [persistence.ts](../../src/core/persistence.ts) 的 EditState version 3 结构，语义不变；version 2 及更早按版本闸整体作废）+ **大纲源文件副本**
- **不缓存解析结果**：打开项目 = 读源副本重新解析 + `mergeRestored` 套回编辑（~0.4s），永远吃到最新解析规则，杜绝"旧解析结果"类 bug（本轮已两次踩坑：旧进程代码、旧存档语义）
- **生成的说明/记录文档不在服务端落盘**（浏览器下载），项目元信息只记 `lastGeneratedAt`——这是"软件不存很多文件"的要点，文档随时可重新生成

## 存储布局

```
数据/
  设置.json              ← 全局参数、主题（不随项目，保持现状）
  项目/
    <hash12>/
      项目.json          ← { meta, edits }
      大纲.docx          ← 源文件副本（hasSource = true）
  日志/                  ← 不变
```

`meta` 结构（[projects.ts](../../src/server/projects.ts)）：

| 字段 | 说明 |
|------|------|
| `id` / `hash` | SHA1 前 12 位 / 完整哈希 |
| `name` | 大纲文件名（最近一次上传/打开时的名字） |
| `addedAt` / `updatedAt` | 建档时间 / 最近活动时间（解析或编辑保存都会刷新） |
| `lastGeneratedAt` | 最近一次生成文档时间（可选） |
| `hasSource` | 源文件副本是否存在（迁移来的旧项目为 false） |
| `stats` | 最近一次解析统计 `{items, cases, steps}`（可选） |
| `progress` | 最近一次编辑保存时的核对进度 `{reviewed, suspects}`（可选） |

> `progress` 由**前端在 `/api/edits` 时随存档上报**——可疑判定规则唯一入口在前端（05 界面设计），服务端不重复实现。

## API

| 接口 | 说明 |
|------|------|
| `GET /api/projects` | 项目列表（meta 数组，按 `updatedAt` 降序） |
| `POST /api/projects/open` `{id}` | 读项目内大纲副本 → 重新解析 → 恢复编辑，**返回结构与 `/api/parse` 完全一致**；无副本时返回 `needsSource: true` |
| `DELETE /api/projects/{id}` | 删除整个项目目录；**id 严格校验 `^[0-9a-f]{12}$`**（防路径穿越） |
| `POST /api/parse` | 上传解析成功后自动建档/更新：写源副本、刷 stats、保留已有 edits |
| `POST /api/edits` | 写入项目文件的 `edits`，同时上报 `progress` |
| `POST /api/generate` | 生成成功后更新 `meta.lastGeneratedAt` |

## 旧数据迁移

服务**启动时执行一次**（`index.ts`）：扫描 `数据/编辑记录/*.json`，version 3（`EDIT_STATE_VERSION`，2026-10-07 复核修正：原文误写 version 2）有效存档按其 `outline.hash` 建项目（`hasSource: false`），导入成功后删除旧文件；目录清空后整个移除。单文件失败跳过不炸主流程。

打开无副本项目 → 界面提示"该项目没有源文件副本，请重新上传原大纲"；重新上传同一文件（哈希相同）即自动补齐副本。

## 界面（第一屏）

- 上传区下方"**最近项目**"列表：项目名、更新时间、统计胶囊（`N 用例 · 已核对 x · 可疑 y`；无副本的标注"无源文件副本"）
- 操作：**打开**（免上传直达第二屏）、**删除**（两段式确认防误删）
- 空列表不显示该区块

## 决策记录

| 决策 | 结论 | 理由 |
|------|------|------|
| 是否存大纲源文件副本 | **存**（用户确认） | 免上传重开项目；解析规则升级后可对旧项目重新解析；删除项目 = 彻底清除涉密副本；编辑记录 JSON 本就含全部步骤文本，敏感级相同 |
| 是否缓存解析结果 | 不缓存 | 解析仅 ~0.4s；缓存会引入"规则升级后打开的还是旧结果"的 bug 类 |
| 生成文档是否落盘 | **v1.3.0 起落盘**到 `数据/生成/<项目id>/`（10-大文档处理 5.3：大产物免浏览器传输，界面展示路径；每次生成覆盖） | 原设计"随时可重新生成，不落盘"在超大文档下被浏览器内存边界推翻；产物落盘 + ≤10MB 保留下载双轨 |
