## 一、需求与拍板（2026-11-20）

| # | 问题 | 拍板结论 |
|---|------|---------|
| 1 | 「不通过」口径 | **只认步骤**：用例表步骤「通过与否」列含 未通过/不通过 即算；**不看问题单标识** |
| 2 | 输出形态 | **一个 docx**，只有 4.1、5、6 三章有内容；其余章节**只保留一级标题**（保证 4.1/5/6 章节号不变），内容不渲染 |
| 3 | 用例属性 | **全部「继承」**（修改类要增删步骤，不做） |
| 4 | 静态三类 | 步骤少（1~2 步），不通过时**直接挪入**，流程与动态用例一致 |

真实记录（03_…测试记录V1.00）实测：步骤结果取值集合恰为 {通过, 未通过}；不通过用例 4 个，覆盖 文档审查/功能/性能/边界 四类。

## 二、输入与匹配

- **大纲**：复用解析层 `extractOutline`；测试项表自带 优先级/需求描述/追踪关系原文/测试项描述 —— 4.1 需求表五个字段**全部原文照抄**，保真零改写。
- **记录**：复用 `extractRecordCases`（`src/core/parse/record.ts`，工具二报告追踪已在用）：每用例表的 步骤「通过与否」数组 + 执行状态 + 问题单。
- **匹配**（记录用例 → 大纲转换行）：三级容差——
  1. `caseId` 精确相等（YL_SU_YZLZ_001 ↔ 转换层 makeCaseId 结果）；
  2. 去尾序号前缀相等（记录 `YL_DC` ↔ 大纲 `YL_DC_001`——真实记录里静态用例标识无尾号）；
  3. 按记录「追踪关系」行的 测试需求标识（XQ_*）定位大纲测试项，该测试项**仅一个用例**时取之；
  仍不匹配 → 告警并默认排除（界面可见，不拦其他用例）。

## 五、API 与界面

- `POST /api/regress/parse`：multipart（记录文件 + 大纲文件或大纲项目 hash）→ 匹配草稿（类型分组、每用例命中步骤号/问题单、告警）；大纲与记录均入项目库（sourceType 复用 outline/record）。
- `POST /api/regress/generate`：{ outline, record, selectedCaseIds, params } → 渲染 .docx，保存 `数据/生成/<项目>/回归测试说明-生成.docx`，响应带 base64 与路径。
- 界面：首页第三张卡「回归测试说明」；两步流程（选大纲+记录 → 预览勾选+生成下载），预览屏按类型分组列出不通过用例（默认全选，未匹配项置灰并给告警文案）。

## 六、配套性纠错（2026-11-20 用户需求"大纲和记录标识不对应要智能识别"）

解析草稿时全量比对两侧数据，异常进 `draft.issues`（界面第一屏告警区自动显示）：

| 代码 | 级别 | 识别内容 |
|------|------|---------|
| REGRESS_ITEM_ID_MISMATCH | warning | 记录表「测试需求标识」与匹配到的大纲测试项标识不一致（大纲改版/记录配错测试项）——真实样本命中：记录 XQ_IO_ZLBJ vs 大纲 XQ_BT_ZLBJ |
| REGRESS_CHAPTER_MISMATCH | warning | 记录追踪关系中的大纲章节号与大纲实际章节号不一致（真实样本命中：6.2.1.5.1 vs 6.2.1.5.1.1） |
| REGRESS_NAME_MISMATCH | warning | 用例名称不一致（去空白后比对；真实样本命中） |
| REGRESS_STEP_MISMATCH | warning | 记录步骤数 ≠ 大纲用例步骤数（真实样本命中：边界 27 vs 28） |
| REGRESS_ID_AMBIG | warning | 记录标识无尾号且测试项下有多个用例——按第一个处理，必须人工核对 |
| REGRESS_NO_RESULT | warning | 用例表无「通过与否」判定，无法确认是否通过（会静默漏判，显式提醒） |
| REGRESS_NO_MATCH / REGRESS_DUP_MATCH | warning | 对不上大纲 / 多表对同一用例（原有） |
| REGRESS_NOT_EXECUTED | info | 执行状态非「已执行」 |
| REGRESS_ITEM_FIELD_EMPTY | info | 大纲侧命中测试项未写优先级/追踪关系/需求描述（4.1 对应格为空） |
| REGRESS_COVERAGE | info | 大纲用例数 > 记录用例表数（真实样本 110 vs 93，有用例未执行/未记录） |

设计原则：**告警不拦路**——匹配照常进行（差异靠用例标识尾号容错），异常只亮出来由人核对；判定口径不受影响（只认步骤未通过/不通过）。

## 八、2026-11-21 第二轮实测修正（WQ 真实大纲+记录脱敏件驱动）

1. **空标题 bug（条件段写法）**：克隆标题段把 `{#firstOfType}{firstOfType}{/firstOfType}` 三标签挤在同一段 → docxtemplater 当**内联条件**处理，空值也保留段落 → 同类型多用例时产出 4.1.2~4.1.16 / 6.2~6.19 一串**仅有编号的空标题**。修正：**三段式**（`{#x}` 独占段 + 标题段 `{x}` + `{/x}` 独占段）——跨段条件对空值正确跳过（验证：null/'' 均跳、真值渲染）。
