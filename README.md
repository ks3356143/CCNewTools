# CCNewTools

测试大纲 → 测试说明 / 测试记录 转换工具。

从一份第三方测试大纲（.docx）中解析测试项表格，经人工核对编辑后，自动生成**测试说明**和**测试记录**两份 Word 文档。替代只能运行在 Windows 上的旧工具（PyQt5 + win32com 方案）。

## 软件说明

**给谁用**：需要依据第三方测试大纲批量编写测试文档的测试人员。

**解决什么问题**：大纲里的测试项表格动辄上百个用例、几百条步骤，人工誊写到两份 Word 文档既费时又易错。本工具把誊写全部自动化——人只做核对与修正，机器负责格式与排版。

**使用形态**：启动后在浏览器里操作（自动打开 `http://127.0.0.1:8300`），三屏流程：

```
第一屏 选择大纲 → 第二屏 核对与编辑 → 第三屏 生成文档
```

**硬性要求**：完全离线运行（无任何网络请求，适合内网环境）、跨平台（Windows / Linux x64，含银河麒麟 V10）、单文件分发（目标机器不需要装 Python / Node / Office）。

## 功能说明

| 功能 | 说明 |
|------|------|
| 大纲解析 | 上传 .docx，自动定位「测试项及方法」章节，解析测试项表格、用例、步骤、通过准则与追踪关系；还原 Word 自动编号的章节号 |
| 问题清单 | 解析问题分错误/警告/提示三级展示，格式有误时支持步骤增删与用例排除兜底 |
| 核对编辑 | 树状目录导航（类型/中间层/测试项/用例四级）；步骤表格单击即改；动作/期望切分可疑处红色标记，徽章点击循环跳转定位 |
| 编辑持久化 | 修改自动保存（防抖），按大纲内容隔离；重开自动恢复，用户手动增删的步骤不丢失 |
| 项目管理 | 一份大纲 = 一个本地项目：最近项目列表、免上传重开（存源副本）、两段式删除；数据不落远端 |
| 全局参数 | 软件配置项名称、测试人员、监测人员等参数一处填写、两份文档共用 |
| 文档生成 | docxtemplater 渲染，产出《测试说明》《测试记录》（含用例清单与需求追踪表），排除的用例不生成；生成不落盘，浏览器直接下载 |
| 界面 | 浅色/深色主题，MD3 风格，零外链资源 |

## 技术栈

- **运行时**：Bun 1.4（服务端 + 测试框架 + 未来单文件编译分发）
- **前端**：Vue 3.5（Composition API）+ Vuetify 4（MD3）+ Vite 8，产物为纯静态资源由本地服务直接托管
- **OOXML 解析**：自研解析层（fflate 解 zip + @xmldom/xmldom 建树），处理标题层级、样式级编号、表格结构
- **文档渲染**：docxtemplater + PizZip，模板即仓库里的两份 .docx（标签语法，样式完全交给模板）
- **无数据库**：数据全部落在本地数据目录的 JSON 与源文件副本中

### 仓库结构

```
src/core/parse/    解析层：.docx → 领域模型（测试项/用例/步骤）
src/core/convert/  转换层：领域模型 → 模板数据（标识生成、动作/期望切分）
src/core/render/   渲染层：模板数据 → docx
src/server/        本地服务：REST API、静态托管、项目管理、日志
web/src/           前端：三屏界面（screens/）与组件（components/）
模板/              测试说明模板.docx、测试记录模板.docx（docxtemplater 语法）
tests/             分层测试（冒烟/解析/变种/转换/渲染/API/项目）
SRS/               需求、设计、进度、踩坑等全部文档
```

## 开发说明

```bash
bun install          # 安装依赖

bun src/server/index.ts   # 启动服务（8300 被占自动顺延）
bun test             # 全量测试
```
